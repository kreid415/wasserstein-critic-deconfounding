## NB-20261003-01 · 2026-10-03T12:08:57-04:00 · DECISION
**Divergence detection: what the non-finite-loss guard counts as 'diverged'**
- author: agent
- decision: NonFiniteLossError (status diverged, PREREG sec. 1) when (a) any loss term a training step computes or back-propagates is non-finite (scVI loss; adv_term, gen_loss, adversary loss and GP; scvi_adv classifier and fool losses), (b) the training forward pass fails torch.distributions argument validation ('Expected parameter ...', e.g. NaN q_m), or (c) a parameter is non-finite after the last optimizer step. The posterior mean is computed with distribution validation off, so a NaN latent is saved and recorded as nonfinite_latent instead of crashing.
- alternatives:
  - (b) and (c) as infrastructure errors: rerun, which repeats deterministically, then the stage stops
  - check only the loss value returned by training_step (misses the adversary terms)
- rationale: (b) is the divergence mode of the 2026-08 sweeps (encoder overflow -> NaN q_m -> ValueError before a loss exists); in (a)-(c) the training objective is non-finite at the current parameters. The guard reads values only (bit identity 34/34 vs 878d8ea).
- decided by: agent (implementation of PREREG sec. 1); flagged to the lead for confirmation

## NB-20261003-02 · 2026-10-03T12:08:57-04:00 · DECISION
**Stage runner policies (scripts/run_stage.py)**
- author: agent
- decision: Infrastructure errors: at most --max-attempts 2 per tag and kind in a run, then no new work is started, running work finishes, exit 5 with the log path. Claims: owner identified by host, /etc/machine-id, boot time, pid namespace, pid and process start; an owner whose liveness cannot be checked (other host, container, sandbox, no machine-id) is 'foreign' and needs --clear-foreign-claims; only verifiably dead owners are 'stale' (--clear-stale-claims). Outputs that break the fitter/scorer contract are moved to OUT/quarantine/, never deleted. Fits read a snapshot of the manifest (OUT/manifests/<sha>.tsv). A scoring-only run skips the fit-device probe.
- alternatives:
  - kill running work on the first exhausted retry
  - treat claims from another pid namespace as stale
  - delete invalid outputs before a retry
- rationale: Running fits are valid work (a stop must not discard them); pids are only comparable within one pid namespace and /proc/sys/kernel/random/boot_id is unreadable in the sandbox; quarantine keeps evidence; a manifest edited during a run must not change fits; JHPCE latents are scored on a host with another GPU.
- decided by: agent (implementation)
- links: repo@757f62f; scripts/run_stage.py
