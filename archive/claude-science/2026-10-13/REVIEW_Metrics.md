## 1. Verdict

- **Cluster launch (this track): GO AFTER FIXES.** The cluster jobs only fit models, so the scorer does not change any fit. Blocking item **M-01** must still be resolved before launch, because the fix decides whether a new tag is needed. The scorer in the review copy uses a 30-nearest-neighbour graph (`scripts/score_scib_native.py:203`). It does not reproduce the stored scores (scorer SHA c88cce3) on 3 of 4 latents. With only that line changed to 15 neighbours, all 4 latents reproduce exactly. If the tag also says 30, then the scorer must be fixed and the tag re-cut before any fit or score is made at it, under the single-commit rule (prereg_rules refuses mixed scorer SHAs).
- **Running local X1 fits: valid.** No scoring code runs during fitting. Any X1 score produced with the copy's scorer (k = 30) is invalid and must be re-scored with k = 15.

## 4. Verified (with evidence)
- **B and C exactly as PREREG §1.** My recomputation from the design text alone matches `prereg_rules.outcomes` on all 1,098 A1 rows and 288 A2/A3 rows: max |ΔB| = max |ΔC| = 0.0 (`bc_check.py`, `bc_recomputed.csv`). The number of bio metrics per task is 6 (atac_small), 8 (immune) and 6 (sim1). There are no failures (failures.csv files hold a header only).
- **Per-task metric availability matches the design.** From the prepped `uns`/`obs` (`inspect_prepped.py`): cell cycle on pancreas, lung, immune and immune_hum_mou; trajectory on immune and immune_hum_mou. The stored scores have cell_cycle and trajectory finite on 531/531 immune rows and NaN elsewhere. No required metric is NaN in any of the 1,431 stored rows.
- **kBET determinism.** tests/scoring + tests/prereg/test_trajectory_metric.py: **15 passed, 0 failed, 0 skipped** (258 s). kBET is identical on all 4 re-scores.
- **kBET per-label handling.** Labels with ≥10 cells and >1 batch are tested; fragmented labels are set to 1 (kbet.py). This matches the scorer's accounting (`kbet_label_flags`, known-answer test passed). `kbet_labels_skipped` is constant per task (1 / 0 / 0), so no R summary read failed.
- **Batch metrics lie in [0, 1] with 1 = best**, as PREREG states. Checked in the scib source (pcr clips at 0, ASW 1−|s|, iLISI scaled, kBET 1−rate, graph_conn).
- **Provenance.** One scorer SHA (c88cce3), dirty = 0, and one set of versions across all 1,431 stored rows.
- **Subsetting.** anndata 0.11.4 drops unused categories when subsetting, so graph_conn and isolated labels do not see empty labels in X3/X8 subsets (toy check).
