## Current compute (from the repo, not from memory; checked at 10a1ca5)

- Tier 1+2 production fits run on JHPCE (Slurm partitions `shared`, `gpu`, `transfer`) with one L40S GPU per job, at most 2 concurrent jobs, and a stop guard; scoring stays local because the JHPCE-vs-local scoring equivalence check (G4) failed (5 of 12 deterministic metrics within 1e-6). Local machine: one RTX 3080 (10 GB VRAM). Environments `wcd-fit` (torch 2.13.0+cu126, same as local `scvi-api`) and `wcd-score` live in `$HOME/envs` (SI-49); caches and data go to fast scratch (nothing in `$HOME`). Sources: `cluster/README.md`, `docs/jhpce/GATE_JHPCE.md`, `docs/jhpce/PRODUCTION_JOB.md`, `docs/WALL_TIME.md`. Submissions need the user's explicit go (see `.claude/rules/compute.md`).

## Historical clusters (kept for provenance and for the pitfalls they taught)

- **[H]** Experiments ran on Rockfish (GPU account and CPU account, lab data directory under `$HOME`, env `wcdenv`) or on DSAI (same layout). Choose by allocation budget and queue depth. Rockfish CPU was effectively exhausted at 24,957.5 of 25,000 core-hours in the July to September window (jobs pend with `AssocGrpCPUMinutesLimit`), DSAI was overdrawn (61,848.8 of 50,000), while the Rockfish GPU account still showed about 78 GPU-hours (re-measured 2026-08-10, which supersedes the earlier "both exhausted" claim). Exhaustion looked calendar-period based; re-measure with `sbalance` before assuming. [mem_0ae985b56112 · observed; mem_ae836fca6b89 · stated; mem_76af659f9a75 · observed; mem_6dbe9cc48f4b · inferred]
- **[H]** DSAI: SLURM partitions l40s, a100, nvl, h100, cpu; conda, module and spack available; figshare reachable; no key-based ssh to Rockfish (so no host-to-host copy). GPU partitions were congested (start estimates 2.5 days out, even for a 5-minute single-GPU job), while the `cpu` partition (about 17 idle nodes of about 60) started jobs at once; working recipe: 16 cores, 64 GB, 24 to 48 h, `--array=0-N%6`. A concurrent Nextflow pipeline can saturate nodes; run staging (env builds, 20 GB downloads) as batch jobs, never on the login node. LaTeX compile checks used `module purge && module load gcc/9.3.0 texlive/20220321`. ## Environments

- **[H]** The earlier cluster environment `wcdenv` was not reproducible from repo files (`pyproject.toml` declares `dependencies=[]`). Build spec used on DSAI: conda python 3.11; pip torch 2.4.1 (CUDA), numba 0.60.0 (0.66 does not exist on PyPI; the LISI fix is numba-version-agnostic), scanpy 1.11.5, anndata, scib 1.1.7, scikit-learn, scipy, pandas, numpy below 2, harmonypy, leidenalg, igraph; then `pip install -e .`. Check `torch.cuda.is_available()` on a GPU node (a cpu-partition build node can report False). The current explicit specs are in `cluster/envspec/` and `envs/*.yml`. [mem_02500bf63439 · observed; mem_6362fb9e84f2 · observed]
- **[H]** The default local `wcd` env had CPU-only torch; a forked `wcd-gpu` env used torch 2.4.1+cu121 (matching the cluster) with nvidia runtime wheels installed `--no-deps`. Use a local GPU only for smoke and convergence tests; a single 8 to 10 GB GPU cannot parallelise a 45-job wave. Always set `KMP_AFFINITY=disabled` and `MKL_THREADING_LAYER=SEQUENTIAL` or torch aborts with OMP error 179. [mem_f381820accfb · observed]
- **[C]** Numba and scanpy versions matter for results: LISI fastmath (numba 0.66) and PAGA/igraph (scanpy 1.9.8 plus igraph 1.0.0) both failed silently or crashed in a sandbox. Record versions with every wave. [mem_6fc4988296f7 · observed; mem_ca02d2e477c3 · observed]

## Job handling

- **[C]** Cluster-side `git push` fails ("could not read Username"): the HTTPS remote has no stored credentials and the GitHub token is not on cluster shells. Commit on the cluster only for what the tasks execute (the dispatcher does not touch git); push from a machine that has the token. Fetch cluster-edited files to that machine first. [mem_6ba6d2d323ca · observed; mem_21e0e4a78193 · observed; mem_edd28c22371c · observed]
- **[C]** A git index-lock race between concurrent tasks once caused exit-128 failures that looked like a backbone bug; the fix is per-task output files and a dispatcher that does not run git. [mem_3def5657f691 · observed; mem_b29b7303e6be · observed]
- **[H]** The GPU removes the compute wall for the critic's 10-step inner loop: cross-species E1-critic went from timing out on CPU to completing on an A100 (9 of 10 lambda at the time of writing). Data prep stays on CPU. [mem_20a4f74385ee · observed]
- **[C]** One config per task; walls from measured runtime; arrays throttled for shared file-system reads (see pitfalls.md). Heavy-dataset prep (HVG + PCA) is CPU-bound and repeated per task. [mem_e6bc4196e9fe · observed; mem_660a61d09103 · observed; mem_a886ff1cb462 · observed]
- **[H]** Raw `sbatch` arrays are only visible through `sacct` and `squeue`; poll those directly. Rockfish interactive ssh intermittently hangs for minutes under load; retry interactive `squeue` before elaborate workarounds. [mem_70a50730ade2 · observed; mem_972f9518dee4 · observed; mem_28c68ea3fc96 · observed]
