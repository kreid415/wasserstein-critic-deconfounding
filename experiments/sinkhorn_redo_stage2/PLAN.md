## How the four traps of the launch review are closed

1. R1 refuses a tag scored twice (prereg_rules.py:306-307) while tier12_v2 still holds the 180 pre-fix Sinkhorn files: every rule step gets an explicit score list with one file per manifest tag, chosen by name by `stage2_rules.py` (v3 folders for every arm; v2 folders only for arms other than sinkhorn; a tag in two folders is an error). The merged failures file is built the same way. The list and its count are written to the step's `scores_list.txt` and `step.json`.
2. Pre-fix Sinkhorn outputs in A1_ext_r1_round1 (18) and A2A3 (36) are refused by the runner (SI-54): the 18 extension and 36 A3 Sinkhorn fits go to NEW folders under `D/tier12_v3` (names in the table below).
3. `freeze_a1_grid.py` has no existence check and would overwrite the tag-frozen extension manifest: every rule step writes into a new `D/tier12_v3/rules/<step>/` folder (refused if it exists) and the tag-frozen files in the repo are never passed as outputs. Repo copies get redo-specific names (step 10).
4. `freeze_matched_lambda.py:123` refuses an existing `--extension-manifest`: the extension manifest path is always inside the new step folder, so it never exists beforehand.

Step folders are written outside the pinned checkout, so the records the rule scripts write carry `git_sha` 10a1ca5 and `git_dirty` false.

## Cost (provisional; PF-16, PF-17)

Basis: pre-fix production `fit_seconds` of the same rows (D/tier12_v2 ledgers, 8 concurrent lanes) times a corrected-code factor. Factor range: 1.45 (the stage-1 preflight's per-task predictions against pre-fix medians: atac_small 1,480 s vs about 1,030 s, immune 3,060 s vs about 2,117 s) to 2.8 (NB-20261013-11, hardest regime, run alone). `docs/cost_model_per_fit.csv` has no Sinkhorn term; it is not used.
